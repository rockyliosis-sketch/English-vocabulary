## 做了什么

- 示例选择前按约定归一化比较英文与原场景：trim、合并空白、转小写、移除末尾 Unicode 标点及空白；内部标点保留，不做模糊匹配。保留剩余顺序，候选池为空回退完整列表；index/total 都按实际候选池计算。
- 轮换仍使用历史复习天数与当天第一次评分前的到期日，同一候选池下刷新和三种评分均不换句。当天编辑原场景或例句池可能改变显示。不承诺跨复习日必换。
- 新增可选 `related_words_json TEXT DEFAULT '[]'`，解析为 `/api/today` 的 `related_words`，不生成复习卡、不参与排期或计数。缺失、非法 JSON、非数组或任一项字段不全时整组降级为 `[]`。
- 背面备注之后、示例之前展示相关词；空组隐藏，切卡清空旧内容，全部使用文本节点。手机单列，较宽的背面区域可双列，按可用宽度换行。
- 准备清理示例及填充相关词两个待审 SQL。相关词草稿覆盖快照 39 个 ID，每词 3 项（下限），共 117 项；包含美式 IPA、词性、简短中文及关系。单音节通常不单独标重音。

## 待执行 SQL 的顺序和作用

本节是后续人工操作顺序，本轮全部未对真实库执行。上线前由 Rocky 核对线上结构和当前数据并保留备份；快照不能作为覆盖线上数据的依据。

1. **先执行一次** `migrations/0002_add_related_words.sql`：只新增相关词列，旧行默认 `[]`。**必须在上线读取该列的新代码之前完成**，否则查询不存在的列会失败。该 ALTER TABLE 不是可重复执行的迁移，按迁移记录核对是否已应用。
2. Rocky 审核后，单独考虑 `scripts/sql-drafts/01-remove-context-examples.sql`：先看文件头的只读预览，再决定是否执行 UPDATE。只修改快照命中的 7 个 ID 的 `examples_json`；按当前数组删除英文与当前原场景逐字相同的项，保序，至少保留一条，不写其它列或复习历史。快照中命中项恰好都是逐字相同，所以使用这个保守条件；线上若改成大小写/空白/尾标点变体会跳过，由运行时完整归一化过滤兜底。其它 ID 不在此草稿范围内。

4. 完成第 1 步后才可上线新代码；第 2、3 步均为可选内容变更，不是上线代码的必需步骤。建议在开始当天复习前统一处理内容，减少当天候选池变化带来的换句。
